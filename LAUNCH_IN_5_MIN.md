# Запуск SAFAR STUDIO PRO

Для первого прослушивания открой `SAFAR_STUDIO_LIVE_PREVIEW.html` с диска и нажми **Слушать**. Сеть и аккаунт для этой версии не нужны. В проекте тот же интерфейс лежит в `public/console.html`.

Пять минут — ориентир для настройки уже подготовленных сервисов. Создание аккаунтов, одобрение магазина, сборка CUDA-образов и первая загрузка весов имеют собственные сроки. В поставке нет оплаченных ресурсов или чужих ключей.

## 1. Получить URL движка

1. Импортируй `DEPLOY_SAFAR_PRO_TO_MODAL.ipynb` в Google Colab. Оставь CPU.
2. Запусти все ячейки. Введи Modal Token ID и Token Secret в два скрытых поля. Альтернатива — секреты Colab `MODAL_TOKEN_ID` и `MODAL_TOKEN_SECRET` с доступом для ноутбука.
3. Дождись строки **GPU-рендер подтверждён**. Ноутбук развёртывает приложение, загружает закреплённые веса, отправляет реальную инструментальную генерацию и проверяет телеметрию мастера. Modal тарифицирует выполненную работу. Рабочая ссылка сохраняется после закрытия Colab, пока приложение развёрнуто в этом workspace.
4. Нажми **Скачать настройки Vercel**. Файл содержит `MODAL_URL` и секрет `SAFAR_GPU_TOKEN`. Сохрани эти значения только на сервере.

Если запуск прервался во время загрузки, повтори ячейку развёртывания. Тома и уже загруженные веса сохраняются. Для диагностики конкретного рендера открой в Modal функции `sketch`, `studio` или `priority`. [Modal deployments](https://modal.com/docs/guide/managing-deployments) · [GPU](https://modal.com/docs/guide/gpu)

## 2. Подготовить Supabase

1. Открой SQL Editor проекта и выполни целиком `supabase/001_studio.sql` один раз. Миграция работает в транзакции. Она использует существующих пользователей Supabase Auth и создаёт таблицы с префиксом `safar_`.
2. Скопируй Project URL, anon/publishable key и service_role/secret key в соответствующие серверные переменные из `.env.example`.
3. В Authentication → URL Configuration укажи публичный адрес сайта в **Site URL** и добавь **https://твой-домен/auth/callback** в Redirect URLs. Для локального запуска добавь `http://localhost:3000/auth/callback`.
4. Включи Email. Стандартное письмо с Magic Link уже подходит. Для входа по цифрам добавь в шаблон письма одноразовый код `{{ .Token }}`. Для реальных адресов пользователей подключи SMTP в Supabase Auth. [Supabase passwordless email](https://supabase.com/docs/guides/auth/auth-email-passwordless)

## 3. Развернуть Next.js

Извлеки ZIP. Корень проекта — каталог с `package.json`. Для проверки на компьютере с Node 22.12+ выполни команды из этого каталога.

```sh
cp .env.example .env.local
npm ci
npm run dev
```

Открой `http://localhost:3000`. Публичный демо-плеер работает до входа. После заполнения настроек аккаунт открывает очередь GPU, сохранённые треки и покупки.

Для Vercel импортируй корень проекта из своего репозитория или выполни `npx vercel` из распакованной директории. В настройках укажи Framework **Next.js**. Команды сборки и cron уже находятся в `vercel.json`. Добавь серверные переменные, затем запусти production deployment. Для Preview и Production используй соответствующие базы и режимы платежей.

| Переменная | Что указать |
|---|---|
| `APP_URL` | Полный HTTPS-адрес сайта без пути |
| `SUPABASE_URL`, `SUPABASE_ANON_KEY`, `SUPABASE_SERVICE_ROLE_KEY` | Настройки проекта Supabase |
| `MODAL_URL`, `SAFAR_GPU_TOKEN` | Значения из ноутбука |
| `CRON_SECRET` | Случайная строка, например вывод `openssl rand -hex 32` |
| `BILLING_PROVIDER`, `BILLING_MODE` | `stripe` или `lemon`, затем `test` или `live` |

## 4. Подключить оплату

**Stripe включён по умолчанию.** Для нового магазина проверь доступность Stripe для страны регистрации бизнеса. Код использует Stripe Checkout и Billing. Налоговая модель стандартного аккаунта Stripe и соглашение Merchant of Record — разные услуги. Определение налогов и выдачу прав на входные записи владелец оформляет для своей юрисдикции. [Stripe availability](https://stripe.com/global) · [Stripe Billing](https://docs.stripe.com/billing/subscriptions/webhooks)

**Быстрый путь для Stripe.** Укажи `APP_URL` и тестовый `STRIPE_SECRET_KEY` в `.env.local`. Команда ниже создаёт в твоём Stripe восемь товаров и цен, endpoint вебхуков и платёжный кабинет. Повторный запуск использует существующие цены с теми же lookup keys. Для рабочего магазина с боевым ключом нужна явная опция `-- --live`.

```sh
npm run setup:stripe
```

Скопируй переменные из приватного файла, путь к которому напечатает команда, в настройки Vercel и повторно разверни фронтенд. Если webhook уже существует, возьми его signing secret в Stripe. Настройки лежат в исключённом из Git каталоге `.safar-private`.

**Путь через дашборд Stripe.** Создай три ежемесячные цены USD и пять разовых по таблице ниже. Создай endpoint `/api/webhooks/stripe` с версией API **2024-06-20** и событиями `checkout.session.completed`, `checkout.session.async_payment_succeeded`, `invoice.paid`, `customer.subscription.updated`, `customer.subscription.deleted`, `charge.refunded`. Включи Customer Portal. Укажи `STRIPE_SECRET_KEY`, `STRIPE_WEBHOOK_SECRET`, `STRIPE_PRICES_JSON` и при наличии `STRIPE_PORTAL_CONFIG`.

**Lemon Squeezy для существующего магазина.** Новые магазины перестали регистрировать 16 ноября 2026 года. Обработка платежей заканчивается 31 марта 2027 года. В действующем магазине выбери `BILLING_PROVIDER=lemon`, заполни `LEMON_STORE_ID`, `LEMON_API_KEY`, `LEMON_WEBHOOK_SECRET` и `LEMON_VARIANTS_JSON`. Создай подписки и варианты по таблице. Подпиши URL `/api/webhooks/lemon` на `order_created`, `order_refunded`, `subscription_created`, `subscription_payment_success`, `subscription_payment_refunded`, `subscription_updated`, `subscription_cancelled`, `subscription_resumed`, `subscription_expired`. Адаптер сверяет подпись, режим, магазин при наличии его ID в событии, вариант и заказ. [Объявление Lemon Squeezy](https://www.lemonsqueezy.com/blog/saying-goodbye-to-lemon-squeezy) · [События](https://docs.lemonsqueezy.com/help/webhooks/event-types)

| Ключ в JSON | Стоимость | Выдача |
|---|---:|---|
| `creator` | $19/мес | 600 CR, XL, WAV, стемы, Repaint, PDF |
| `pro` | $49/мес | 2 000 CR, 1 LoRA в месяц, Sync Pack, клиентский A/B, API и отдельный GPU-пул |
| `label` | $149/мес | 8 000 CR, владелец и 4 участника, LoRA без месячной квоты, batch и брендированный плеер |
| `top500`, `top2000` | $12 / $39 | 500 / 2 000 CR |
| `stems`, `sync` | $3 / $9 | Соответствующий пакет одного выбранного трека |
| `lora` | $19 | Один проход обучения |
| FREE | $0 | 30 CR при регистрации и ежемесячное начисление при использовании, MP3 192, 12-секундные превью стемов, личная лицензия |

Каждому ключу JSON соответствует фактический Stripe Price ID или Lemon Variant ID. Бесплатный план создаёт база данных. Трек и Repaint расходуют 10 CR. Текстовый анализ A&R через Qwen расходует 1 CR. Пасс LoRA при сбое возвращается. Реферальная ссылка находится в аккаунте. После первой положительной оплаты оба участника получают по 100 CR.

## 5. Приёмка перед открытием продаж

1. Войди с двух тестовых адресов. Заверши покупку тестовой картой провайдера. Повторно доставь событие из панели провайдера. Сверь один платёж, одно начисление и бонусы в `safar_payments`, `safar_ledger` и `safar_referrals`.
2. Создай Sketch, затем Studio XL. Успешная задача получает SHA-256, телеметрию и временные ссылки на аудио. В **Студия и лицензии** доступны форматы, разбор дикции и сертификат. Вычислить SHA-256 скачанного мастер-WAV можно через `sha256sum Master.wav`.
3. Выдели такты и создай Repaint. Для скачанного результата проверь `outside_max_abs_diff`. В **Студия и лицензии** можно также загрузить исходник для cover, style transfer и vocal-to-BGM.
4. На Pro обучи LoRA из 5–10 собственных файлов. Выбери ту же базу Turbo или XL при следующем рендере. Сравнение для клиента создаётся из двух готовых треков, срок ссылки — 30 дней. Для скачивания четыре версии формируются по сохранённому мастер-рендеру. Изменения локальных фейдеров слышны в консоли и экспортируются в Reel.
5. После первого входа владельца назначь его администратором в SQL Editor. Подставь его реальный UUID из Authentication → Users.

```sql
update public.safar_users
set is_admin = true
where id = current_setting('app.owner_user_id')::uuid;
```

Для указанного выше запроса предварительно задай `app.owner_user_id` в том же SQL-сеансе через `set app.owner_user_id = 'UUID владельца';`. Можно также включить `is_admin` у нужной строки в защищённом Table Editor.

Открой `/admin/economics`. MRR показывает активные возобновляемые подписки. Выручка — продажи за месяц за вычетом учтённых возвратов. Внеси фактические расходы на GPU, процессинг и прочие услуги по каждому тарифу. Маржа появляется после этой сверки. Оценка GPU строится по секундам выполнения задания и не включает всю стоимость простоя контейнера, cold start, CPU, томов, налогов и платёжных споров. Владелец учитывает их по своим счетам. Цена $0.015–0.03 и маржа 80% служат целями измерения. [Modal pricing](https://modal.com/pricing)

## Обслуживание очереди

Завершение GPU-задачи отправляет подписанное уведомление в HTTPS-приложение. Сервер проверяет статус непосредственно в Modal перед commit/refund. Дополнительная сверка выполняется при открытии сессии и по Vercel Cron ежедневно в 03:00 UTC. На тарифе Vercel с частыми cron можно задать `*/5 * * * *`. После аварийного завершения контейнера применяется крайний срок задания. Повторная отправка с тем же UUID сохраняет одну бронь и один результат.

Предыдущий v4.1 и новый `safar-studio-pro` могут работать одновременно. Для переключения приложения достаточно сменить `MODAL_URL` в серверной конфигурации. Остановка приложения в панели Modal останавливает вычисления, а удаление томов уничтожает сохранённые файлы.
